# 企劃與遊戲循環

## 從新主題到可製作規格

把教材、對象、故事與參考遊戲整理進 `docs/game-brief.md`。必要資訊缺少時才詢問；未指定的風格、數量可提出小規模方案，標成建議。使用者指定的交付量優先，不將打樣規模當成最終交付量。

先定義「玩家能學會什麼」及「玩家每回合做什麼」，再寫世界觀。例如：五年級分數比較 → 辨識等值分數與大小 → 正確操作修復星艦；不要只把數學題貼在英文版角色上。

| 項目 | 要回答的問題 |
|---|---|
| 學習 | 對象、先備能力、可觀察目標、題型、語言、程度與複習策略 |
| 故事 | 主角動機、同伴作用、章節轉折、每關推進哪件事 |
| 循環 | 首頁→選目標→準備→行動→回饋→結算→成長→下一關 |
| 規則 | 回合、HP／MP、勝敗、傷害、技能、重試、獎勵與解鎖條件 |
| 美術 | 母版、風格、角色／敵人／背景清單、比例、圖集契約與用途 |
| 畫面 | 手機主視圖、主按鈕、展開內容、長題與錯誤狀態 |
| 交付 | 本輪範圍、內容量、執行方式、驗收與尚待決定事項 |

## 先製作完整的小段遊戲

未指定規模時，可先以一位主角、一個同伴、一個場景、三關和足夠不重複樣題驗證核心循環。這是建議起點，不是硬性配額。

先確認第一關可進入、可敗可勝、可領獎並保存，才擴充章節和收藏數量。企劃模式停在規格與樣題，不自動製作遊戲。單純改題庫也不強加整套新美術流程。

章節表使用穩定 ID：`chapterId / stageId / learningObjectiveIds / enemyId / backgroundId / questionPool / reward / unlockCondition`。故事、題目和獎勵要能解釋為何在這一關出現；不按字母或資料檔順序直接排課。

## 手機介面與戰鬥節奏

首頁優先顯示下一個能開始的目標。模式多時拆成「選模式→選目標→準備」，不要同屏要求玩家同時理解程度、章節、難度、敵人、裝備和題型。

以 390×844 草擬戰鬥：固定狀態列、敵我 HP、場景、題區、選項與操作列。長文可捲動，選項與解析可完整讀取；不要為追求首屏而截斷文字。桌面擴大場景和欄位，不只拉長手機畫面。

選定技能呈現方式後寫進目前設計稿。阿瓦隆曾從頭像展開能力改成直接顯示四個技能；兩者是版本選擇，不要求新作品同時套用。每個技能顯示作用、成本、不可用原因，不能遮住題目。

進場、答對、答錯、勝敗與領獎都有可辨識回饋。演出結束前鎖定重複作答，長對話與倒數可略過；減少動態模式保留相同資訊。

## 可選系統

換裝、同伴、敵人收服、被動、抽取、無盡與 Boss 按主題與需求選用，不因原作有就全部加入。若有隨機收藏，寫清機率、保底與免費取得方式；外觀稀有度不當作學習能力證明。

數學選項可用數式，國語可用繁體中文，英文依需求使用英文題面與繁中解析。只有使用者選英文版時才沿用全英文選項規則。
