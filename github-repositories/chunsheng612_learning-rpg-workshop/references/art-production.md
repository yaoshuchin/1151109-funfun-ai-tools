# 美術與動畫

## 素材契約與追蹤

先在 `reference/art-production/catalog.json` 列 ID、用途、母版、提示、檔名、比例／尺寸、透明需求、朝向、圖集格線、動作列、錨點與狀態。主角可用 H00、同伴 M00、敵人 E001、背景 B00；命名是範例，沿用既有清楚規則即可。

每項分別追蹤 `generation / review / integration / verification`，避免把生成完成當作遊戲完成。記來源圖路徑、執行版路徑、消費元件與問題；路徑相對於專案根目錄。範本見 `assets/art-catalog.json`。

## 角色母版與逐張製作

先選定主角、同伴與一張背景的風格基準，再擴充。母版記固定臉型、髮色、辨識物、武器、剪影、光源與色盤；換裝改結構、材質與配件，保留身分，不只改色。

生成與編修使用環境提供的圖片工具。透明需求傳入工具的透明選項，不能只寫在提示詞。角色變體帶母版參考，編修先檢視原圖。每次生成一個排定交付單位；多個角色不要合成一張拼貼冒充多張獨立交付，sprite sheet 本身則是一張合法單位。

提示包含：ID 與用途、固定身分、這張變化、構圖／方向、安全留白、風格、透明或場景需求、不得出現的 UI／文字。背景留出敵我站位與題區可讀空間，另檢查手機裁切。成功後立刻保存原始圖、提示／參考來源與狀態，再做下一個 ID。

使用者已要求全部完成時，依清單持續製作，不逐張再問。工具限額、不可用或連續同因失敗時記最後完成 ID、待做 ID 和原因，保留斷點；不重複交付相同圖，或把提示草稿算成圖片。

## 立繪轉執行素材

立繪、頭像、縮圖與動作表分開驗收；立繪完成不表示動畫完成。原系列常用下列契約，可按遊戲改動，但須同步更新 renderer：

| 素材 | 參考契約 |
|---|---|
| 主角／敵人立繪 | 全身、腳底與武器完整，透明背景，保留邊界 |
| 章節背景 | 16:9，無角色與 UI，手機裁切保留站位 |
| 阿瓦隆動作表 | 4 欄×4 列，1024×1024、單格 256×256；idle／weaponAttack／magicAttack／hurt 各四格 |
| 文道問劍主角 | 舊版另有 4 欄×5 列；不能用四列契約直接切 |

逐格檢查 alpha、格線、動作順序、腳底或漂浮中心錨點、武器／披風跨格及同排外觀。棋盤格若畫在 RGB 裡就不是透明；尺寸與 alpha 自動檢查不能替代目視確認方向與動作。

另建動態審稿頁：逐排播放、接觸表、放大、翻轉預覽、格線與錨點。待機不漂移、出招面向對手、受擊後回待機；不要只看整張圖集就放行。

優先用圖片工具做生成與編修；後處理遵守當時工具能力與使用者選擇，不把未授權的外部模型當自動替代。格式／尺寸轉換另存執行版，不覆寫唯一母檔。

## 接入與載入

品質確認後把執行版放入 `public/assets/` 或等效資產目錄，更新 manifest 和真正畫面消費端。ID 不能只在展示頁卻沒進遊戲。

首頁只載當前角色和必要場景，圖鑑用縮圖，進場只預載當場角色、敵人和背景。狀態分 loading／ready／failed，整批必要預載可採原作 3000ms 上限；超時有可辨識替代，稍後成功可換正式圖，不困在 loading。

缺圖用同身分名稱／ID／符印替代，明確標記佔位，不冒充正式美術。正式素材保留版本或內容雜湊；替換同路徑快取檔時更新 service worker cache。
