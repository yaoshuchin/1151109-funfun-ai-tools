# 學習與題庫

## 從教材到題目

保留來源資料，另建概念／詞義清單，再編寫題目與解析。教材清單、單字清單、題目草稿和可玩題庫是不同產物；下載到詞表不能宣稱已有同數量的完成考題。

來源清單記錄標題、作者／機構、網址或本機檔案、取得日期、版本與適用範圍；確認使用方式，不把公開可讀當作可整份重製。有官方考試定位時查當時官方資料；原創練習可稱某考試風格，不冒稱官方真題或保證分數。

先做代表題型與難度的小批題目，驗證第一關能使用，再批次擴充。章節配額按概念設計，不用不同角色名稱掩蓋重複模板。

## 建議的內容契約

沿用既有型別，以下為新作可調整的最低欄位，不要求舊專案改格式：

```ts
type LearningQuestion = {
  id: string;
  objectiveId: string;
  chapterId: string;
  kind: string;
  difficulty: string;
  prompt: string;
  passageId?: string;
  options: { id: string; text: string }[];
  correctOptionId: string;
  explanation: string;
  distractorReasons: Record<string, string>;
  sourceIds: string[];
  reviewStatus: 'draft' | 'checked' | 'approved' | 'disputed';
};
```

`checked` 表示做過內容檢查，不等於教師／真人複核；審稿紀錄記 reviewer 類型、日期與問題。若專案要求人工核准，只有實際人工確認才可 `approved`。原型可依需求啟用已檢查題，但標明品質，不把 AI 自評寫成人工校訂。

## 品質閘門

- ID、題面與正解組合去重；答案指向存在的選項，選項非空且不重複。
- 一題有明確主要學習目標；四選一只是原系列慣例，其他題型按目標設計。
- 正解唯一且由題幹／文章推出；每個干擾項有錯因。第二答案也合理時修題，不用「最佳答案」掩蓋歧義。
- 解析說明理由與常見誤解。英文詞義不在題幹洩漏答案，數學檢查算式、單位與圖示一致。
- 難度按概念與語句判斷，不從玩家等級或服裝稀有度推算。短文組保留可回看的全文。
- 來源檔名、PDF 抽取過程與生成提示不進題面和劇情；必要署名放適當的教材／關於頁，不隱去授權要求。

驗證錯誤帶題目 ID、欄位與原因。報告分開列總量、狀態、章節／難度／題型覆蓋、重複與爭議題；結構檢查通過不代表教育內容正確。

## 選題與複習

開戰時固定本場題目 ID，作答途中不重新抽整份題庫。同場避免重複，按章節、概念、程度與已檢查狀態篩選，兼顧到期複習、弱項與新題。替換題符合本場規格且未出現；無題可換時說明原因且不扣 MP。

題池不足時回報需要數與可用數，修正關卡或補題；備用池只能按企劃定義的範圍使用，不能靜默塞入未審稿、其他章節或不同難度。洗牌選項用 ID 維持正解，不沿用舊索引。

學習紀錄區分首次獨立作答、提示後作答、重答與換題。戰鬥可以因技能獲勝，掌握判斷仍依學習證據；錯題可在結算後複習，不要求玩家花遊戲貨幣看正解。
