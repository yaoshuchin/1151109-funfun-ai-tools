# 程式、戰鬥與存檔

## 新作與複製既有作品

新作可沿用 React＋TypeScript＋Vite；這是原系列基線，不綁固定套件版本。沿用 lockfile，新增依賴或 API 先查官方文件。使用者指定技術或既有環境不同時依其選擇。

複製只帶原始碼與需要的授權素材，不搬 node_modules、dist、快取、帳戶憑證或舊雲端設定。先列需隔離的名稱：package、品牌、localStorage key／版本、IndexedDB（若有）、PWA manifest、service worker cache、部署目標、Firebase 專案與資料路徑（若有）。同 origin 不同路徑的遊戲也要避免 service worker scope 互相覆蓋。

## 模組責任

| 層 | 放什麼 |
|---|---|
| 內容 | 劇情、關卡、題庫、敵人、技能定義、素材 manifest |
| 規則 | 選題、傷害、勝敗、技能、獎勵、存檔 migration |
| UI | 畫面流程、按鈕、HUD、題目、動畫、無障礙狀態 |
| 媒體 | 預載、sprite renderer、BGM、音效、朗讀 |
| 儲存 | 本機保存、匯出／匯入、選配雲端同步 |

小幅修改不全面重構舊 App；新增規則優先放可單獨驗證的函式。UI 由狀態渲染，不從 CSS class 推算勝敗。技能文案與效果共用規則表，不只做特效而沒改數值。

## 戰鬥狀態與正確性

可採：`preload → intro → answer → resolving → feedback → answer / won / lost → result → reward → next`。先寫清終局優先序、題數耗盡、同時歸零、收服／放棄與離開，再接動畫。

阿瓦隆後期採「玩家 HP 歸零敗北；敵人 HP 歸零勝利；題數用完敵人仍活著則敗北」，曾有舊文件寫只要存活就結算。延續原作以當前 `battleRules.ts` 與 App 查證；新作由企劃選擇，不混用兩套規則。

- 答案只處理一次，resolving 期間鎖定重送；動畫結束再進下一狀態，避免結果蓋掉攻擊。
- 正解、反擊、HP／MP、連擊、學習紀錄同一次狀態轉移更新。
- 技能先驗可用性，再扣 MP 和套效果；無作用時不扣。本題／本場效期明訂。
- 提示只排除錯項；重答記首次失誤，按規格保護一次傷害／回合，不能刷獎勵。
- 換題維持題型、難度與本場唯一性；無候選時留在原題。
- 領獎只記一次；返回與下一關經同一結算邏輯，避免漏領、多領。
- 初始裝備全對有合理通關路徑。改 HP、傷害、題數或 MP 時做數值模擬，不要求抽稀有裝備才能過第一關。

## 音效與朗讀

音樂按首頁、地圖、普通戰、Boss、結算映射，不逐題重建播放器。首次玩家互動後解鎖，靜音、切場景與熱更新清理需一致。

命中音效對準接觸時刻，受擊特效指向受擊方，施法由真正施法者演出。若有朗讀，開始時暫停或降低配樂；end、error、取消／切頁都收尾，尊重玩家當下靜音設定。聲音替身能測事件，不能宣稱實際聲音已聽過。

## 存檔

離線本機儲存先成立：帶 schemaVersion、正規化／migration、例外處理，保存進度、收藏、設定、學習紀錄。匯入先驗資料，無效檔不覆蓋好存檔；匯出不含登入 token。

雲端按需求加入。Firebase 為原系列選項，需驗本人資料存取規則、登入網域與衝突策略；不僅因 updatedAt 較新就無條件覆蓋另一裝置進度。換 Firebase 專案時一起核對前端設定、Auth helper origin、Authorized domains 與 collection。不把 service account 或管理金鑰放前端。

複製的 Avalon 仍帶 legacy storage／firebase 檔時，追蹤實際消費端；檔案存在不代表功能已啟用，也不代表應自動接上。
