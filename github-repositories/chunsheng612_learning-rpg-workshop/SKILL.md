# 自學 RPG 遊戲製作工坊

用繁體中文協作，把學習內容做成玩家的行動：讀題、作答、出招、看解析、獲得成長，再挑戰下一關。本流程提煉自《文道問劍》→ 英文版 →《誓劍阿瓦隆》，可替換學科、年齡、角色和世界觀；原作的章節數、服裝數、能力數不是新作品的預設需求。

## 先判斷本次要做到哪裡

- **企劃模式**：「先規劃／設計／給我藍圖」。產出可實作企劃、樣題、素材清單與驗收條件；不自行進入整套製作或部署。
- **製作模式**：「做出來／開始製作／全部完成」。在既有授權內完成可玩版本、素材接線與驗證；先跑通一小段完整遊戲，再擴充到約定規模，不以企劃書代替遊戲。
- **延續模式**：「繼續／換學科／補圖／改善玩法」。先讀現況與進度，完成指定部分，沿用可用內容；不要從頭重生全部資產。

查看工作區 README、package scripts、設計稿、內容資料、素材 manifest 與執行入口。僅在找不到必要資訊時詢問；非必要選項提出合理假設後繼續。優先釐清會改變成果的三件事：學習對象與目標、世界觀與玩法、這次交付範圍。既有教材先讀再規劃，避免讓使用者重述。

開始時簡述採用此 Skill、預計交付與採用的假設。使用者已要求直接製作或整批繪製時，不另加逐階段確認門檻。

## 製作流程與讀取時機

1. **定義作品**：用 [企劃與遊戲循環](references/game-design.md) 寫清楚學習目標、核心循環、故事／章節、玩法、畫面與完成條件。新專案可用下方初始化工具建立企劃檔。
2. **題庫先打樣**：讀 [學習與題庫](references/learning-content.md)。先完成能驗證題型與學習回饋的小批樣題，接入第一關後再擴量。題庫草稿、已檢查與已啟用分開統計。
3. **定型美術**：讀 [美術與動畫](references/art-production.md)。先定角色母版與一個場景，再按素材 ID 逐張生成；立繪與動作表是不同交付品。用進度表保留中斷點。
4. **完成遊戲**：讀 [程式、戰鬥與存檔](references/implementation.md)。先跑通首頁→準備→答題→攻防→解析→勝敗→領獎→下一關，再做收集、換裝、技能或雲端功能。
5. **玩家驗收**：讀 [測試與交付](references/qa-release.md)，驗證實際瀏覽器流程、手機可讀性、失敗分支與內容品質，再處理發布。
6. **發布或封裝**：只做使用者要求的範圍；發佈前核對新作品的部署與存檔身分。使用者已授權部署時，檢查完成後直接執行，無須重複詢問。

若在本機原專案中工作，讀 [原作對照與查證入口](references/original-projects.md) 可節省探索。Skill 不依賴原專案路徑才能運作。

## 保留這些製作經驗

- **以遊戲循環組織介面**：入口、目標、準備逐步揭露；每屏有明確主行動。戰鬥同時保有題目、血量、作答餘額與回饋；長題文仍可閱讀。
- **遊戲數值與學習紀錄分開**：提示、重答、換題與增傷不能把受輔助的作答冒充獨立掌握；裝備和抽取不改答案與學習等級。
- **身分明確**：關卡明確引用敵人／素材／題目 ID。圖片、名稱、技能與收服對象共用同一筆資料，不靠陣列位置推算；缺圖保留同身分符印，不借另一隻敵人充數。
- **技能要真的生效**：效果、消耗、可用條件與玩家文案來自同一規則；滿血治療、無替換題或魔力不足等無效操作不扣資源。
- **素材可用不等於檔案存在**：記錄已生成、已審查、已接入、已驗證四階段；沒驗收的素材不可因檔名符合就上線。角色原始圖與執行版分開保存。
- **離線能玩**：本機保存先成立，雲端依需求加入。新作品使用獨立 save key／版本、service worker cache 與部署名稱。
- **以實作查證現況**：舊企劃可能與後來程式不同。描述目前行為先查實際消費端、資料與驗證；提出新規格時同步更新規則、文案和測試。

## 新專案企劃工具

`scripts/create_game_brief.py` 只建立製作文件，不建立遊戲程式、產圖或部署。由 Skill 所在位置解析腳本路徑：

```bash
python3 scripts/create_game_brief.py /absolute/path/new-game \
  --title '星海算術遠征' --subject '分數與比例' \
  --audience '國小五年級' --theme '星際探險'
```

輸出 `docs/game-brief.md`、`docs/production-status.json`、`reference/art-production/catalog.json`。任何目標檔已存在就停止，不覆寫。繼續既有專案時直接更新原文件，不重新初始化。

## 工具與範圍

沿用專案可用工具。原系列用 React、TypeScript、Vite；新作可沿用，使用者指定其他技術時依其選擇。新增套件、外部服務或部署設定前查當時的官方文件，不照抄舊版本設定。

圖像生成／編修使用環境提供的圖片工具；修改前先檢視目標圖，角色變體帶入母版參考。若工具不可用、限額或缺必要來源，保留已完成項目，標明阻礙與待續 ID；不拿重複圖、程序圖形或提示詞冒充已完成的正式 AI 美術。低風險可修正錯誤最多連續嘗試三次，同一限制持續存在就停止該批重試，繼續不受影響的工作。

不因載入 Skill 自動更動正式站、帳戶、雲端規則或產生整批圖片；依本次任務及既有授權行動。功能缺少外部工具時先完成可做部分，說明具體缺口，不另建無關帳戶或切換服務。

## 完成時

給出實際可開啟的遊戲／企劃路徑、完成範圍、驗證結果與待辦；素材數分別報告生成、審查、接入、驗證數，題目數分別報告草稿、已檢查與啟用數。若部署，回報實際網址與線上檢查結果；未跑過的瀏覽器、真人聽音或雲端同步，不宣稱已驗證。
